Evolve the program; evaluate its packing

This classroom example uses the problem in AlphaEvolve, Appendix B.12: place 26 or 32 variable-radius circles in a unit square and maximize their summed radii. The public results repository does not release AlphaEvolve’s engine. This implementation supplies its own controller, initial programs and evaluator, and uses TAMU Luna. It does not embed a published arrangement or claim a record.

What is optimized?

A circle is (x, y, r). Its radius must be nonnegative; x and y must both lie between r and 1−r. Every pair must have center distance at least the sum of their radii. Tangency is allowed. The objective is Σr, not covered area. Zero-radius circles are allowed and counted explicitly. The final geometry is checked within a disclosed 10⁻⁹ tolerance; this is floating-point verification, not an exact mathematical certificate.

Why is radius allocation a linear program?

Once the centers are fixed, their pairwise distances are constants. For every circle, r is at most its distance to the closest wall. For every pair, rᵢ+rⱼ is at most the known center distance. Maximizing Σr under these constraints is a linear program. The trusted helper radii(centers) uses SciPy’s HiGHS solver with a common construction margin of 10⁻⁸. Finding the centers remains a nonconvex search problem.

Two-center example: centers (0.25, 0.5) and (0.75, 0.5) permit radii 0.25 each, with total 0.5. Moving them to (0.3, 0.5) and (0.7, 0.5) does not permit radii 0.3 each: their distance is only 0.4, so the circles would overlap by 0.2. A larger claimed sum does not pass the independent evaluator.

Who writes and who executes a proposal?

Luna returns JSON containing round_id, real parent_ids, a testable hypothesis, and a source string. That string defines actual Python solve(initial, seed, steps). Luna writes the proposed code. The local Python interpreter executes that code inside Bubblewrap. Python does not infer a task from prose. A syntax/signature check precedes execution; independent geometry checks follow it.

The supplied names are NumPy (np), math, radii and report. The latter streams intermediate witnesses. The server verifies each displayed witness. A complete returned packing supplies a trial score; three complete trials supply program fitness. A failed or timed-out program has no eligible median even if an earlier progress witness was valid.

What enters the context?

The task and constraints, interface and budgets, trial seeds, selected parent source, trial measurements, tried IDs and failure history. Structure-only mode withholds the trial scores and history. Parents are ordered by stable ID in both context conditions. Independent generation receives no parent source and must return an empty parent list. Checkboxes choose the initial population only; they do not restrict future source to the checked methods.

The page shows the actual provider request body and public response while the call runs. Authorization and hidden reasoning are excluded. Keys are not embedded in the page, source or recorded context. Numerical seeds control starts and stochastic numerical moves, not Luna’s response.

Two published problems, one evolutionary mechanism

Demo 1 uses 26 circles; Demo 2 uses 32. Both match the unit-square objective in Appendix B.12. Use three gated calls for each: propose a child, incorporate its measurements, then inspect another adaptation or plateau. Their raw scores are not directly comparable because the circle count changes.

The default iterative-refinement mode passes the previous best packing for each seed to the next round. Before comparison, freeze that bank and re-evaluate all parent programs on it. The child receives copies of the same bank. Every evaluation records a bank identity; old-bank fitness is retained as history, not mixed into current selection. The fixed-start option instead keeps the original seeded bank throughout a run.

Several initial algorithms and three numeric seeds do not constitute an island model. Top-three selection does not guarantee behavioral diversity. No short run establishes record performance or broad generalization.

Three ways to preserve different search behavior

Islands evolve separate populations and occasionally exchange programs. Multi-dimensional Archive of Phenotypic Elites (MAP-Elites) retains a strong program in each declared behavior bin. Novelty search favors behavior far from earlier observations. These are design extensions; the current controller uses top-three quality ranking.

Illustrative programs, measured under identical conditions: C scores 2.420 and D scores 2.415, both using one-center moves with no restarts. B scores 2.410 using coordinated moves and occasional restarts. Ordinary top-two ranking keeps C and D. A two-bin behavior archive keeps C and B, preserving a different way to search. Those are invented scores, not observed Luna results. Actual descriptors require instrumenting moves and restarts; different source text alone is not behavioral novelty.

Primary definitions: Mouret and Clune, MAP-Elites; Lehman and Stanley, novelty search.

Quality, numerical cost and stopping

Illustration: policy A obtains median sum 2.40 in one numerical second; B obtains 2.41 in five. Neither dominates in quality and time. A chosen utility U=S−αt with α=0.01 sum-units per second gives A=2.39 and B=2.36. With α=0.001, B instead wins: 2.405 versus 2.399. The price expresses a declared preference; it is not a universal constant or a measured API tariff.

Our demo ranks quality and reports costs separately. It applies no source-length penalty, utility price or Pareto archive. Model generation cost belongs to the search path, not intrinsically to a program. Distinguish marginal evaluation time, API usage and total preparation cost. A predeclared plateau rule could stop further requests; this controller instead enforces its call/time caps and supports explicit Stop.
