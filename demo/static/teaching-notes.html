2. Optimization as search

When the best candidate is unknown, what can we do besides guess once?

Define a candidate space 𝒜\mathcal A and a measurable objective FF. Seek

a*∈argmaxa∈𝒜F(a).a^*\in\arg\max_{a\in\mathcal A}F(a).

Generate candidates → measure them → spend the next trial where the evidence suggests it may help.

Optimization is an evidence-guided search. An evolutionary algorithm adds a population, inherited variation and selection.

The candidate may be a parameter vector, a program or a design. An optimizer does not need to enumerate the whole space, but it needs an operational definition of quality. A candidate that sounds plausible is not a measured result. Our objective can be computed automatically, which lets repeated search use the same external check.

Begin with evolutionary computation itself. Language models are introduced later as one possible variation mechanism. This ordering separates the optimization framework from the technology used to propose a change. It also makes a numerical-only baseline meaningful: the framework does not require a language model to define or evaluate a candidate.

3. Population and fitness

Why keep several candidates instead of only the current champion?

A population stores alternative structures. Fitness measures each candidate under a declared evaluation protocol.

Illustrative scores: A = 5, B = 7, C = 6. Keeping B and C preserves two starting points for the next variation step.

A population supplies material for inheritance and exploration. Its size and selection rule determine what information survives.

The numbers here are an illustrative maximization example, not Max-Cut measurements. A population retains candidates together with evidence about their quality. Selection can preserve a champion and other useful alternatives. Population size alone does not guarantee diversity: several programs may implement nearly the same behavior.

In the classroom controller the population cap is three and ranking is deterministic. There is no reserved diversity slot, island migration or tournament sampling. Those are possible design choices, not hidden features of the example. The population contains solver programs; a later execution of a solver produces a separate solution witness.

4. Variation, evaluation and selection

What turns repeated candidate generation into an evolutionary algorithm?

Mutation can perturb a parameter, replace a component or compose stages. Selection compares parents and children using the same fitness protocol.

Useful structure is inherited, varied and tested. Elitism retains measured parents when a mutation is worse.

A classical variation operator can make random parameter edits, replace a subtree in a program or combine material from parents. Variation does not have to improve fitness. The evaluator supplies evidence and selection decides which structures remain. Carrying parents into the enlarged pool prevents an unsuccessful child from automatically erasing the incumbent.

Chapter 10 distinguishes initial generation from survivor-conditioned mutation. Its recurrence selects parents, generates variants, pools parents and children, then selects again. Here the controller retains prior measured scores, so elitism protects the observed leaderboard under the fixed protocol. That is not a theorem about expected quality on new trials or eventual global convergence.

5. Exploration and exploitation

Should the next mutation refine a strong candidate or try a different mechanism?

Exploit: adjust a promising parameter or refine an existing composition. Explore: replace a stage or try another algorithm family.

Too little variation can collapse the population. Too much unconstrained variation can waste evaluations on poor candidates.

Variation and selection must balance inheritance with discovery. Better starting material may help; a weak start does not imply permanent failure.

The search neighborhood is defined by the representation and mutation rules. An operator limited to small parameter changes explores a different neighborhood from one allowed to replace a kernel. Strong selection can remove useful alternatives; weak selection can spend resources on low-quality programs. The controller exposes complete-trial ranking and exact-duplicate rejection but does not implement a general diversity guarantee.

The distinction matters for the initialization experiment. Checkboxes choose the initial population only. They do not remove unchecked kernels from the artifact space. A language-model mutator may therefore recover a useful algorithm absent from the initial suite. Claiming that a poor suite can never reach the reference would contradict that permitted search space.

6. The language-model mutator

What changes if the variation operator can read programs and measured feedback?

A large language model reads selected programs, trial outcomes and allowed edits, then proposes a motivated mutation.

For example: retain a vector-relaxation stage, then append local search to improve the rounded assignment. The proposal is a hypothesis.

The LLM supplies context-conditioned variation. The harness still supplies fitness. Its weights are not trained during this run.

The model replaces one part of the evolutionary algorithm: the variation operator. It does not replace the artifact representation, objective, evaluator, selection rule or external population memory. Between calls, the controller changes the context; it does not update model weights. The same selected structure and failure record can make the next proposal more informed than an independent guess.

Chapter 10 connects context engineering to mutation and evaluation to fitness. FunSearch is a primary program-search example (Romera-Paredes et al. 2024). The classroom system uses a narrower interpreter over existing numerical kernels. Its proposals can change configurations and compositions but cannot invent arbitrary executable Python or modify the objective. Better proposals are possible, never guaranteed.

7. Signed Max-Cut

How should vertices be partitioned when some edges prefer separation and others prefer agreement?

Positive edge: prefer different sides. Negative edge: prefer the same side.

CG(s)=∑(i,j)∈Ewij1−sisj2,si∈{−1,+1}.C_G(s)=\sum_{(i,j)\in E}w_{ij}\frac{1-s_i s_j}{2},\quad s_i\in\{-1,+1\}.

Maximize the original signed cut. The comparison uses 1,000 vertices, 5,043 signed edges and reference 1098.

A solution witness is one integer sign per vertex in original order. A crossing contributes its signed weight; an uncut edge contributes zero. Thus leaving a negative edge uncut avoids a penalty rather than earning an extra positive reward. Complementing every sign gives the same objective. The four-vertex picture is an illustration; the live comparison uses the supplied sparse random signed graph.

Both initialization experiments use the same 1,000-vertex graph, 5,043 edges and raw random assignments for seeds 3, 4 and 5. Its supplied reference is 1098. The separate dense stress case has 100 vertices, 4950 real-valued signed edges and reference 402.5209. It tests another numerical structure; fewer vertices and greater density do not imply a universal hardness ordering. Neither reference is a certified optimum. The earlier 100-vertex torus recordings are historical and remain preserved.

8. Local moves and feasible witnesses

Can the search move to a worse state while keeping a better result?

Flip one sign, si←−sis_i\leftarrow-s_i, with exact gain

Δi=si∑j:(i,j)∈Ewijsj.\Delta_i=s_i\sum_{j:(i,j)\in E}w_{ij}s_j.

The exploratory assignment may worsen. A separate best-so-far copy preserves the strongest valid witness seen during that execution.

Separate the moving state, best witness and strategy fitness. Only a complete evaluation makes a strategy eligible for ranking.

Only terms incident to the flipped vertex change; their differences sum to the stated gain. Cached gains make local moves inexpensive. Numerical methods can accept neutral or worsening moves to escape a basin while retaining the best feasible assignment separately.

This distinguishes three levels. The strategy is a program. Executing it produces a sign vector. The evaluator recomputes that vector’s objective and summarizes three trials into strategy fitness. A witness from a censored trial may be valid even though the program is ineligible for complete-trial selection. A zero-cut partition is legal; a vector of zero-valued signs is not.

9. Solver programs

What can Luna edit if the assignment itself is not the evolving artifact?

A program has one to three stages: algorithm, configuration, work cap and start rule.

bm(max_sweeps=20, rounding_count=8); retained
→ bls(max_work=9000); retained

Execute a program → obtain signs → recompute the original cut → summarize three trials → rank the program.

Evolve the solver; evaluate its witness. Trusted kernels execute the stages. Unchecked algorithms remain available to the mutator.

The identifiers bm and bls denote the rank-two Burer–Monteiro method and Breakout Local Search. The displayed composition was proposed in the earlier genuine dense-graph rehearsal. Each schema stage contains backend, config, max_work and fresh. Missing defaults are normalized before hashing so equivalent encodings cannot receive separate evaluations merely by omitting a default.

A retained stage receives a copy of the best witness from preceding work in the same trial. A fresh stage uses a seeded random exploratory start; the interpreter retains an older better witness if the new stage is worse. Remaining numerical time is allocated among remaining stages, with unused time carried forward. The model supplies data describing this bounded interpreter, not shell commands or arbitrary source code.

10. Four numerical algorithms

Which mechanism changes when we choose a different solver stage?

Tabu Search: best admissible flips, temporary reversal bans and aspiration. Simulated Annealing: temperature-dependent acceptance of random flips.

Breakout Local Search: improving descent followed by adaptive perturbations. Rank-two Burer–Monteiro: unit-vector refinement, projection to signs and polish.

Acceptance, memory, escape and representation are different design levers. Full examples and parameter meanings are available in the algorithm guide.

Tabu Search maintains current signs, one-flip gains, tabu expiry and a separate best witness. It flips the highest-gain admissible vertex even when the gain is nonpositive. Seeded ties are reproducible. A flip at iteration t sets expiry to t+tenure+1; aspiration admits an otherwise prohibited flip if it would beat the global incumbent. restart_after=0 disables a stagnation restart. The work cap is 20000 iterations.

Simulated Annealing proposes a uniformly selected vertex and accepts a gain Δ with probability min(1,exp(Δ/T)). Temperature falls geometrically over the proposal budget. A logarithmic comparison avoids unstable exponentiation; optional bounded improving-flip polish shares the trial clock. The cap is 200000 proposals.

Breakout Local Search alternates steepest improving descent and perturbation. Repeating the same local optimum can increase jump magnitude. Its adaptive mechanism chooses directed tabu single/pair moves or random perturbation. The controls jump, stagnation, p_min, q and tenure_min/max govern that choice; the cap is 12000 individual flips. These work units are not interchangeable with tabu iterations or annealing proposals.

The Burer–Monteiro-style implementation uses two-dimensional unit vectors, coordinate refinement, projection directions and discrete polish. It allows one solve with at most 60 sweeps and 16 directions. An encountered nonconvex relaxed value is not a certified Max-Cut upper bound. Warm signs participate in the preserved extended path and remain eligible for retention. All 133 hashed reference files stay unchanged; classroom adaptations live outside the vendor snapshot.

17. Reading solver evidence

Which record proves that a solver improved: the graph, the hypothesis or the completed trials?

Require original-order integer signs and a matching graph hash. Recompute the objective from the original signed edges with two scoring paths.

Rank complete programs by median, minimum, fewer stages and stable genome ID. Retain a valid best witness separately, including one from a censored trial.

Selection follows complete measured evidence. Preserve failures, timeouts and plateaus so students can inspect the full mechanism.

A valid witness answers a feasibility-and-quality question for one execution. A complete candidate ranking answers how its program performed across the declared trials. Neither the model’s hypothesis nor an attractive partition drawing supplies fitness. Incomplete programs receive no eligible median/minimum ranking entry, even if all returned witnesses happen to match the reference.

Changing work limits can trade quality against completion risk. The exact-exchange and comparison pages expose requested programs, measured execution time, actual token usage where supplied, invalid proposals and survivor decisions. Calls after a target has already been achieved are visible as teaching continuation. No extra activity or artificial solver motion is fabricated to fill the allotted demonstration window.

18. The agentic evolutionary framework

Can we now name the five choices we implemented?

(𝒜,f,μ,σ,P0)(\mathcal A,f,\mu,\sigma,P_0): artifact space, fitness, mutation, selection and initial population. Checkboxes choose P0P_0; they do not change 𝒜\mathcal A.

Qt∼μ(⋅∣Pt,Ht,Bt),Pt+1=σ(Pt∪E(Qt)).Q_t\sim\mu(\cdot\mid P_t,H_t,B_t),\quad P_{t+1}=\sigma(P_t\cup E(Q_t)).

HtH_t: measured history. BtB_t: remaining budget. EE: validation and complete evaluation.

The LLM is the mutation operator inside an externally measured evolutionary loop. For the course minimization convention, f(a)=−medianjCG(Aa(G,zj))f(a)=-\operatorname{median}_j C_G(A_a(G,z_j)).

This instantiates Chapter 10, Definition 10.2, after the audience has encountered both ordinary evolutionary search and the LLM variant. The artifact space contains validated programs of one to three trusted stages. Its interpreter maps graph G and shared raw start z_j into signs under the seeded numerical protocol. Negative median cut turns maximization into the course’s lower-is-better fitness convention. The implementation supplements that primary scalar with minimum cut, stage count and stable identity tie-breaks.

The chapter presents an artifact-to-artifact mutation operator. The operational notation here makes context, stochasticity and budget explicit: one tool-free call may refer to up to three selected parents and return at most two children. Q_t is the proposed set; E(Q_t) retains only admitted, completely evaluated children. Selected programs and their measured histories inform the next request. The model’s parameters remain fixed; learning during the run is carried by external context and population memory.

Elitism preserves observed measured strategies under this protocol, not global optimality, diversity or unseen-instance quality. Initial population design and allowed artifact-space design are separate levers. In this tutorial all checked and unchecked trusted kernels remain available to mutation in every comparison.

19. Applying the framework to research

Which component would be hardest to supply honestly for your own research problem?

Specify the artifact, automatic evaluator, mutation context, survivor rule and initial population. Declare budgets and a success criterion before running.

Use domain knowledge, compare strong numerical baselines, and test unseen instances before claiming generalization.

Build trustworthy measurement and inspectable data flow first. Then decide where a language-model mutator earns its cost.

Transfer the framework by replacing components deliberately. A scientific expression may be scored by prediction error and complexity; an experimental protocol still needs a definition of executable evidence. If no reliable automatic evaluation exists, measurement design is the next task. The algorithm guide and separate architecture document let a researcher inspect the system before adapting it.

FunSearch supplies a prominent program-search example (Romera-Paredes et al. 2024). AlphaEvolve operates at a broader algorithm-evolution scope (AlphaEvolve team 2025), while OpenEvolve is an independent open-source implementation (OpenEvolve contributors n.d.). This classroom interpreter evolves configurations and compositions of existing kernels. It demonstrates the mechanism without claiming new kernel synthesis, broad model superiority or global convergence. The teaching sequence follows Chapter 10, especially Definition 10.2, Figures 10.1–10.2 and its discussions of context, elitism, diversity and cost.

Appendix A1. Server architecture

What coordinates the browser, numerical search and model?

One loopback server owns run state and workers, serves every teaching page, and streams events to the browser.

The server orchestrates; workers execute; events explain. The API key stays in the server-side client.

The diagram shows responsibilities, not a collection of independently deployed services. HTTP requests use a standard-library ThreadingHTTPServer on 127.0.0.1:8766. Manager permits one active run. A Run thread owns its sequence of serial numerical trials and model calls. Numerical and model workers are bounded child subprocesses with PID/start-tick ownership. Original-edge checking happens both inside the numerical adapter and again in the controller; the scorer box is not a separate network service.

The browser never directly calls TAMU. It creates a run, starts it, advances explicit round gates and subscribes to server-sent events. The same server hosts presentation, demo, guide, exact exchange, architecture and teaching notes. Switching views or reconnecting only reads existing state; it cannot start another paid request. The separate architecture document maps every route, module, message and trust boundary in more detail.

Appendix A2. The API request and context

What is actually sent when we press “Send parents to Luna”?

model: protected.gpt-5.6-luna
messages:
  system: instructions + response schema
  user: serialized round context
stream: true; tools: []

Context: up to three genomes and trial evidence; failures and tried IDs; algorithm defaults, bounds and remaining budget. The worker adds HTTPS authorization separately.

The context carries measured search memory. Solution vectors, reference answers and the API key are excluded from the model’s context.

At an explicit round gate, Run.propose selects the measured survivors and constructs a JSON context through proposals.context. Parent records contain normalized stages, median, minimum and three trial records, including elapsed numerical time, stage counters and completeness. The context also includes attempted genome identities, actual validation or incomplete-trial failures, initial solver selection, graph size and signedness, the raw-start rule, allowed defaults, parameter bounds, stage work caps and remaining wall time.

The model receives two Chat Completions messages: a system message with instructions plus the required JSON schema, and a user message containing that context. The TAMU client sends a streamed HTTPS POST to https://chat-api.tamu.ai/api/chat/completions with the protected Luna model, max_completion_tokens=2400, low reasoning effort and no tools. Authorization is a server-side header, not part of the displayed body. The proposer is not given the assignment vectors, stored numerical preset, replay, benchmark name or reference target. The exact-exchange page displays the actual recorded request body and public return, rather than a reconstructed example.

Appendix A3. Response and loop closure

When does streamed text become a candidate that can survive?

Public chunks → completed JSON → known parent IDs → schema, bounds and duplicate checks → admitted stage program.

Owned numerical trials → independent original-edge scores → complete-candidate ranking → new survivors and failure feedback for the next request.

Text is a proposal until validated and measured. Server-sent events expose progress; selection supplies the next mutation context.

model_worker.py projects public content and completion metadata from the provider stream, excluding hidden reasoning fields and authorization. A watcher emits actual public deltas to the browser. A completed response must be valid JSON with the required round ID, known parent IDs, hypothesis, mutation category, up to two children and any plateau reason. Each child is checked independently; invalid parameters and duplicate normalized genomes are rejected without a silent fix or free retry.

Admitted children run through backend.py in owned processes. The controller checks their graph hash and independently rescored witnesses. Incomplete candidates cannot enter the survivor ranking, even when their best witness is valid. Each event is appended to an ignored run log and streamed by SSE with a sequence number. Reconnection uses an event cursor and never launches paid work. A genuine recorded replay reproduces these events, keeps a persistent replay label, and reveals its public response only when the recorded timeline reaches that response.
